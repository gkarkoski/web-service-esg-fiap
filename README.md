# ESG Training Management

ASP.NET Core 8 REST API for mandatory corporate training, certification expiry, and ESG compliance.

## Architecture

MVC is adapted to a Web API, as agreed with the course professor: Models represent the domain, Controllers handle HTTP, DTOs define API contracts, Services implement business rules, and EF Core handles persistence. There is no frontend or Razor view; DTOs are not views. All code and API names use English. The original solution filename is retained for Rider compatibility.

```text
web-service-esg-fiap.sln
src/EsgTrainingManagement.Api/
  Controllers/  DTOs/  Models/  Enums/  Services/
  Data/Migrations/  Validators/  Exceptions/  Security/
tests/EsgTrainingManagement.Tests/
  Controllers/  Services/  Data/
collections/EsgTrainingManagement.postman_collection.json
scripts/
Dockerfile
.dockerignore
```

## Configuration and execution

The command examples use PowerShell 7 (`pwsh`). Choose either local .NET execution below or Docker execution in the Docker section; the Docker option does not require a local .NET SDK.

Install the .NET 8 SDK, including the ASP.NET Core 8 runtime. A newer SDK can build net8.0, but API execution and HTTP tests still need ASP.NET Core 8. Oracle SQL generation targets Oracle 19 compatibility, with NUMBER(1) booleans. Use Oracle 19c or newer and permissions to create tables, indexes, constraints and identity columns.

Supply Oracle credentials through environment variables to use the database-backed endpoints. appsettings.Example.json shows the configuration format.

```powershell
$env:ConnectionStrings__DefaultConnection = 'Data Source=oracle.fiap.com.br:1521/ORCL;User Id=SEU_RM;Password=SUA_SENHA;'
$env:ASPNETCORE_ENVIRONMENT = 'Development'
dotnet tool restore
dotnet restore web-service-esg-fiap.sln
dotnet build web-service-esg-fiap.sln --no-restore
dotnet run --project src/EsgTrainingManagement.Api -- --urls http://localhost:8080
```

Replace Oracle placeholders locally. Keep actual credentials outside tracked files and ZIPs. The API starts with a random in-memory JWT signing key when `Jwt:SigningKey` is empty or omitted. Sign in again after restarting the API. To keep tokens valid across restarts or instances, configure the same private key of at least 32 bytes through `Jwt__SigningKey` or user-secrets. The default token lifetime configured in appsettings.json is 180 minutes.

The evaluator needs valid Oracle credentials and network access to the FIAP server. They can use their own schema with the required permissions, or receive access to the demonstration schema privately. The Oracle schema normally matches the database username. API demonstration logins do not grant direct database access. The application does not load credentials from AGENTS.md, and the delivery does not include database passwords.

For repeated local execution from Rider, configure .NET user-secrets once instead of setting variables for every terminal. Secrets are stored in the current user's profile, outside the repository:

```powershell
dotnet user-secrets set 'ConnectionStrings:DefaultConnection' 'Data Source=oracle.fiap.com.br:1521/ORCL;User Id=SEU_RM;Password=SUA_SENHA;' --project src/EsgTrainingManagement.Api
dotnet run --project src/EsgTrainingManagement.Api --launch-profile http
```

Replace placeholders locally. In Rider, select the `http` launch profile from launchSettings.json, which sets Development and port 8080. User-secrets are loaded only in Development; running the executable directly without that environment does not load them. Docker and other machines still need their own configuration. Environment variables override user-secrets when both are set.

Outside Testing, a configured connection triggers MigrateAsync followed by the idempotent seed. Connection or migration errors fail startup. Without a connection, the API starts and logs that the database was not initialized. Database-backed routes require an Oracle connection.

Swagger is available at [http://localhost:8080/swagger](http://localhost:8080/swagger) in Development. Log in through POST /api/auth/login and enter the returned token in Authorize. Public demonstration accounts configured in appsettings.json:

| Email | Password | Role |
| --- | --- | --- |
| admin@esg.com | Admin@123 | Admin |
| auditor@esg.com | Auditor@123 | Auditor |

Replace DemoUsers configuration and use a private JWT key for real deployment. Admin can write; Admin and Auditor can read. Login is anonymous.

## Database

The initial Oracle migration, designer and snapshot were generated by dotnet ef and remain in Data/Migrations. A second generated migration aligns boolean metadata without changing column types. Apply migrations manually with the connection configured:

```powershell
dotnet tool restore
dotnet ef database update --project src/EsgTrainingManagement.Api
dotnet ef migrations has-pending-model-changes --project src/EsgTrainingManagement.Api
```

Employee PKs and record FKs use the Oracle provider's native GUID mapping to RAW(16). Employee creation generates Guid.NewGuid(). Enums use explicit integer conversions, strings use explicit lengths and VARCHAR2, and scores use NUMBER(5,2). Unique indexes protect normalized employee numbers and emails; FK and common filter indexes are included.

Seed individually completes the three fixed roles and inserts four example trainings, twelve requirements, five employees and twelve records. It does not overwrite operational edits or refresh existing dates on reseeding. Initial dates are relative to the injected UTC clock.

| Seed employee GUID | Initial state |
| --- | --- |
| 00000000-0000-0000-0000-000000000001 | Compliant |
| 00000000-0000-0000-0000-000000000002 | Expired, except lifetime training |
| 00000000-0000-0000-0000-000000000003 | ExpiringSoon, except lifetime training |
| 00000000-0000-0000-0000-000000000004 | Pending |
| 00000000-0000-0000-0000-000000000005 | WithinDeadline |

## Endpoints

All routes require Bearer authentication except login. All writes require Admin. Creation responses include Location; linking a requirement returns 204. Roles and departments cannot be created through the API.

| Method | Route | Behavior |
| --- | --- | --- |
| POST | /api/auth/login | Return token and expiration |
| POST / GET | /api/employees | Register / list employees |
| GET | /api/employees/{employeeId:guid} | Employee details |
| POST / GET | /api/trainings | Create / list trainings |
| GET | /api/trainings/{trainingId:int} | Training details |
| GET | /api/job-roles | Roles and mandatory trainings |
| POST | /api/job-roles/{jobRoleId:int}/trainings/{trainingId:int} | Link mandatory training |
| POST / GET | /api/training-records | Record completion / list history |
| GET | /api/training-records/{recordId:int} | Completion details |
| GET | /api/compliance/employees/{employeeId:guid} | Compliance dossier |
| GET | /api/compliance/issues | Active employees' outstanding obligations |
| GET | /api/compliance/esg-indicators | Company adherence by ESG pillar |

Lists accept pageNumber (default 1) and pageSize (default 10, maximum 50), and return items, pageNumber, pageSize, totalCount and totalPages. Invalid pagination returns 400. Filters: employees use jobRoleId/isActive; trainings use esgPillar/title; records use employeeId/trainingId; issues use status/department. Each issue row represents one employee-training obligation. Queries use no tracking, DTO projections, deterministic ordering, database counts and database pagination. Indicators aggregate in the database.

## Enums and validation

Use enum strings in JSON. Unknown values are rejected. Explicit numeric codes are stable storage identifiers.

| Enum | Values and codes |
| --- | --- |
| EsgPillar | Environmental = 1, Social = 2, Governance = 3 |
| Department | Operations = 1, HumanResources = 2, Finance = 3 |
| JobRoleType | Operator = 1, PeopleAnalyst = 2, FinanceAnalyst = 3 |
| ComplianceStatus | Compliant = 1, ExpiringSoon = 2, Expired = 3, WithinDeadline = 4, Pending = 5 |

Employee creation receives jobRole as a fixed enum string; its integer jobRoleId is returned and used in routes/filters. Employee numbers are trimmed and uppercased, and emails trimmed and lowercased. Dates must be UTC timestamps ending in Z; admission and completion cannot be future dates. Training duration must be positive, validity is 0-1200 months, deadlines are 0-36500 days, scores are optional values from 0 to 10 with at most two decimals, and certificate codes have a 60-character limit.

HTTP responses: 200 for reads/login, 201 for resource creation, 204 for links, 400 for validation, 401 for missing/invalid authentication, 403 for insufficient roles, 404 for missing resources, 422 for duplicate employee identifiers/requirement links, and 500 for unexpected failures. Domain and unexpected exceptions use RFC 7807 ProblemDetails and do not expose internal details.

## Compliance rules

Expiry is completedAt.AddMonths(validityMonths); zero validity means lifetime and expiresAt null. For each mandatory requirement, consider the record with the latest completedAt, then the highest ID as tie-breaker. All comparisons use an injected TimeProvider and UTC.

| Status | Rule |
| --- | --- |
| Compliant | Lifetime or expiry strictly after now + 30 days |
| ExpiringSoon | now < expiry <= now + 30 days |
| Expired | expiry <= now |
| WithinDeadline | No record and now < hire date + deadline days |
| Pending | No record and now >= hire date + deadline days |

Expired records remain Expired rather than Pending. Admission deadlines only apply when no record exists. Optional requirements are excluded. Issues include only Expired, Pending and ExpiringSoon, and reject other status filters. Inactive employees are available in dossiers/history but excluded from issues and company indicators.

Adherence is (Compliant + ExpiringSoon) / (Compliant + ExpiringSoon + Expired + Pending) * 100. WithinDeadline is excluded from the denominator. No due obligations means 100% with a due count of zero. Percentages round to two decimals, midpoint away from zero. Indicators always include all three pillars.

## Tests

```powershell
dotnet test web-service-esg-fiap.sln
```

HTTP integration tests use WebApplicationFactory, Testing, unique InMemory databases and real JWT login. Oracle context registrations are replaced and Oracle migrations never run in Testing. Every controller has exact HTTP 200 assertions. Tests also cover authorization, GUID creation, validation, safe errors, seed idempotence, calendar expiry, deadline boundaries, latest history, and adherence. Unit tests use fixed clocks. Oracle tests inspect mappings and generate SQL without a server; they do not prove real database execution or a GUID round trip through Oracle.

## Docker

Prerequisites

- Install and start Docker Desktop or another Docker engine configured for Linux containers.
- Extract the source ZIP and open PowerShell 7 in the directory containing Dockerfile.
- Allow internet access for the initial .NET image and NuGet downloads.
- To use endpoints that read or write data, have valid Oracle credentials and network access from the container to oracle.fiap.com.br:1521, including any institution-required VPN.
- Keep host port 8080 available. No local .NET SDK or Oracle installation is required for this option.

Configure the environment in that same terminal, build the image, and start the API.

```powershell
$env:ConnectionStrings__DefaultConnection = 'Data Source=oracle.fiap.com.br:1521/ORCL;User Id=SEU_RM;Password=SUA_SENHA;'
docker build -t esg-training-management .
docker run --rm -p 127.0.0.1:8080:8080 -e ASPNETCORE_ENVIRONMENT=Development -e ConnectionStrings__DefaultConnection esg-training-management
```

The Dockerfile uses a multi-stage build and a non-root runtime user. The API listens on port 8080 inside the container. The command publishes it on port 8080 on your machine. To use another host port, for example 8081, use `-p 127.0.0.1:8081:8080` and update the browser URL and Postman `base_url`. [Docker port publishing](https://docs.docker.com/engine/network/port-publishing/)

Development enables Swagger for the local demonstration. The default environment is Production, where Swagger is disabled. For a quick check of Swagger and login without Oracle, omit `-e ConnectionStrings__DefaultConnection`. For database operations, replace the Oracle placeholders in your shell. On startup, migrations and seed run against that configured schema. Pass `-e Jwt__SigningKey` if you configure a persistent signing key in the shell.

In **Docker Desktop**, go to **Images → Run → Optional settings**. Enter host port `8080` in the row for container port `8080/tcp`. Add `ASPNETCORE_ENVIRONMENT` with value `Development` and, for database operations, add `ConnectionStrings__DefaultConnection` with your Oracle connection string. [Run an image from Docker Desktop](https://docs.docker.com/desktop/use-desktop/images/#run-an-image-as-a-container)

Open [http://127.0.0.1:8080/swagger](http://127.0.0.1:8080/swagger), run the login request with the demo Admin account and enter its token under **Authorize**. If Swagger shows `Failed to fetch`, open [the OpenAPI JSON directly](http://127.0.0.1:8080/swagger/v1/swagger.json). It should return HTTP 200. Check `docker ps` for a mapping to container port `8080/tcp` and `docker logs <container>` for `Hosting environment: Development`. If Docker cannot connect to its daemon, start Docker Desktop or your Docker engine. Oracle connection or migration errors appear in the container logs and stop startup.

Press Ctrl+C in the terminal running `docker run` to stop the container. The `--rm` flag removes the stopped container. Oracle data stays on the external server.
